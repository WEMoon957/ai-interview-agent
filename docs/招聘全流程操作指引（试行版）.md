# 招聘全流程操作指引（试行版）

> **适用系统**：AI 招聘系统（interview-agent）  
> **适用对象**：HR / 门店店长 / 老板  
> **版本**：v1.1　｜　更新日期：2026-10-20（初版 v1.0：2026-10-14）  
> **本次更新**：新增「老板终试 + 录用审批」环节；汇总改为自动落库；到店直招录音改走飞书妙记；补齐账号、角色与权限说明

---

## 一、这份文档怎么用

试行期内，从「发岗位、看简历、约面试」到「定人选、发 offer」，全部在这套系统里跑通。本文按**你实际操作的时间顺序**写，每个环节都告诉你三件事：

- **谁来做** —— HR、门店店长、老板，各管一段
- **在哪里做** —— 登录 http://129.204.61.73:3000 ，按角色自动落到对应首页
- **做完会怎样** —— 系统自动做什么、飞书会推给谁

遇到文档没覆盖的问题，请在《飞书试用反馈收集表》里记一条（见第十一节）。

### 1.1 账号与初始密码

> 账号与初始密码见飞书文档原文，**不写入代码库**。系统共四个角色：admin（管理员）、hr（人力资源）、store_manager（店长）、boss（老板）。

> **密码规则**：首次登录后请在右上角「修改密码」自行改掉初始密码（改密会踢掉其他设备上的登录）。系统**不开放注册**，新账号只能由管理员在「账号管理」页创建；店长账号按门店需求创建。连续输错 5 次会锁定 15 分钟，登录状态保持 12 小时。

### 1.2 四个角色各能看到什么

| 角色 | 后台能看到 | 主要动作 |
|-|-|-|
| admin | 全部页面 | 建账号、配权限、兜底处理 |
| hr | 概览、岗位、公司介绍、面试模板、简历初筛、AI 面试记录、线下复试、评分报告、数据汇总、录用 / 入职、妙记授权 | 初筛、发面试链接、复试、汇总查看、发 Offer |
| store_manager | **只有**「线下复试」 | 约面、现场面试并录音（飞书妙记）、到店直招建档 |
| boss | **只有**「老板操作台」 | 确认终面时间、终试拍板、审批 HR 提交的 Offer |

菜单按角色自动收敛：看不到的页面不会出现在左侧，直接敲网址也会被送回本角色的首页。

## 二、全流程一图看懂

```
准备：建岗位 → 配面试模板 → 写公司介绍
  │
  ▼
① 简历初筛（HR 上传简历文件夹，AI 逐份打分排序）
  │   达标者自动生成 AI 面试链接，推卡片 + 建飞书待办
  ▼
② AI 面试（候选人点链接自助作答，约 15~30 分钟）
  │   综合分达标自动推 HR 飞书
  ▼
③ 线下复试（HR 约面 → 店长现场面试并录音 → HR 录入分数与结论）
  │   录完分即自动重算汇总，候选人进入「待终试」
  ▼
④ 汇总自动落库（三阶段分数聚合，无需人工点按钮）
  │   自动推「复核 + 办 offer / 入职」提醒
  ▼
⑤ 老板终试拍板 → HR 提交 offer → 老板审批
  │   终试通过 + 最终分 ≥ 65 才能发起 offer
  ▼
办入职
```

| 阶段 | 谁来做 | 系统做什么 |
|-|-|-|
| 准备 | HR | 建岗位、配面试模板、维护公司介绍 |
| ① 简历初筛 | HR | 上传岗位文件夹，AI 按 JD 逐份打分并排序 |
| ② AI 面试 | 候选人 | 自助作答，AI 自动追问并逐题评分 |
| ③ 线下复试 | HR（录入）／店长（只录音） | 约面、现场面试、录音；分数与结论由 HR 在后台录入 |
| ④ 汇总落库 | 系统自动 | 聚合三阶段分数写快照，推复核提醒 |
| ⑤ 终试与录用审批 | 老板 | 终试拍板；审批 HR 提交的 Offer |

> **一句话概括**：HR 上传一个岗位文件夹，系统自动初筛排序并把面试链接推到飞书；候选人自助完成 AI 面试；店长线下复试时只用飞书妙记录音、后台自动抓取并转写评分，HR 在后台确认分数与结论；系统自动汇总落库；**判「不推荐」的直接结束、不进终试**；老板在操作台确认终面时间并拍板、审批 offer；HR 发出 offer 并办入职。

## 三、开始前的一次性准备

这三件事做一次就够，之后一直复用。

### 3.1 建岗位（在「岗位管理」页）

1. 点「新建岗位」，填**岗位名称**（如：店员、后厨、店长）、JD 描述、技能要求
2. 保存后岗位出现在列表里
3. 岗位可切换**免初筛**开关：开启后，上传简历跳过 AI 打分，直接发 AI 面试链接（详见第五节）

### 3.2 配面试模板（在「面试模板」页）

模板决定「AI 考什么、怎么评分」：

1. 点「新建模板」，选择所属岗位
2. **预设问题**：建议 3\~5 题。每题可选题型：

   - **主观题**：候选人自由作答，AI 评分
   - **选择题**：候选人单选，系统按预设正确答案确定性判分，不消耗 AI
3. **评分维度**：设置维度和权重，**权重之和必须等于 1**（系统默认已给四个维度）
4. **追问上限**：每题最多追问几次（默认 2，填 0 表示不追问）

> **建议**：文化匹配类问题（如「我们正处于快速开店期、节假日最忙，你能接受吗？」）很适合放一道在题集里，配合第三节 3.3 的公司介绍一起用。

### 3.3 写公司介绍（在「公司介绍」页）（对应打电话介绍公司这一环节）

这是本次试行新加的环节，**写一次，之后所有面试自动带上**。

1. 进入「公司介绍」页，写清四件事：

   - **公司是谁**：品牌、主营业务、门店规模
   - **现状如何**：发展节奏、旺季时段、近期重点
   - **团队氛围**：相处方式、管理风格
   - **用工特点**：班次、节假日安排、晋升路径、福利
2. 点「保存」，页面下方会实时预览**候选人打开链接时看到的开场白**

**三条要记住的规则**：

| 规则 | 说明 |
|-|-|
| 快照隔离 | 发起面试时把当时的介绍快照进这场面试。**之后再改介绍，只影响之后发起的面试**，已发出的面试仍用旧内容 |
| 只展示前 300 字 | 开场白只带前 300 字，超出部分仅后台留存（页面有字数提示） |
| 留空不影响 | 没写介绍时，开场白走通用文案，不影响任何流程 |

## 四、五个阶段的逐步操作

### ① 简历初筛（HR）

在「简历初筛」页：

1. 上传**岗位文件夹**（一个文件夹 = 一个岗位的多份简历），选择对应岗位
2. 系统逐份解析简历（支持 PDF / Word / 文本），按 JD 四维打分：技能匹配、经验相关、稳定性、素质与态度
3. 上传完成后得到一张**降序榜单**，展示每人的总分、亮点、风险

**系统自动做的事**（达到门槛者）：

- 生成 AI 面试链接
- 推一张卡片到 HR 飞书（岗位、本次统计、推荐名单含链接）
- 建一条飞书待办（含候选人、分数、面试链接、截止时间）
- 自动重算该岗位的汇总快照

也可以点「推送榜单给 HR」手动补推。

### ② AI 面试（候选人自助，HR 无需在场）

候选人打开链接后：

1. 先阅读并同意《安全知情协议》
2. 看到**开场白**（含公司介绍）
3. 逐题作答，回答不够深入时 AI 会**自动追问**
4. 答完显示「面试已完成」

**系统自动做的事**：逐题评分 → 维度加权 → 生成百分制报告（含录用建议与维度雷达图）；**综合分达到阈值时自动推 HR 飞书**；同时重算该岗位汇总。

HR 侧可在「AI 面试记录」页查看所有人的链接与状态，在「评分报告」页看详情。候选人中途退出不会丢进度，重新打开即可继续。

### ③ 线下复试（HR / 店长）

在「线下复试」页，顶部是**「待 HR 处理」列表**（初筛达标 + AI 面试完成的人会进来）：

1. 点「约面」，填时间、地点、面试官、面试官角色（HR / 店长）
2. 面试结束后录入：**百分制总分 + 维度明细 + 评语 + 结论**（通过 / 待定 / 淘汰）
3. 若候选人临时未到，可标记状态，避免悬空

**到店直招**（候选人直接到门店，没有简历）见第五节。

### ④ 汇总自动落库（系统自动，HR 只需查看）

在「数据汇总」页：

1. 选岗位，系统**实时聚合**三阶段分数：初筛分、AI 面试分、线下复试分
2. **落库已改为自动**：初筛上传完成、AI 面试出报告、复试录完分，任一事件都会触发该岗位重算并写快照，**不需要再点按钮**
3. 页面可查看最新快照、导出 CSV；需要强制重算时点「重新落库」即可
4. 落库后系统自动推「复核 + 办 offer / 入职」提醒卡片与待办

**最终加权分** = 初筛 × 0.2 + AI 面试 × 0.4 + 线下 × 0.4。

> **缺环节不惩罚**：如果某人不走初筛或不走 AI 面试，系统会对**已有环节重新归一化**，不会因为缺环节而拉低分数。  
> **自动落库失败不阻塞业务**：初筛、面试、复试照常进行，到数据汇总页点「重新落库」兜底即可。

### ⑤ 终试与录用审批（老板）

复试录完分后，候选人自动进入老板的待终试队列，**并同时推送一条飞书消息 + 待办给老板**（收件人由 `FEISHU_BOSS_OPEN_IDS` 配置）。老板登录后默认落在「老板操作台」（**/console/boss**），页面只有两块队列：

**队列一：待终试（走完复试，等老板确认终面时间并拍板）**

1. **先确认终面时间**：点行内「安排终面」（已约过则显示「改期」），选日期时间、可填地点备注；时间会显示在列表的「终面时间」列，未约则标「待安排」
2. 点「面试档案」先看材料：维度对比表（初筛 / AI 面试 / 复试统一折算成 10 分制横向对比）、优点、风险、终试待确认问题、各环节明细；抽屉底部可「复制追问清单」带到现场

> **判「不推荐」的人不会出现在这里**：HR 在后台录入线下复试结论时选「不推荐」，候选人直接结束、不进待终试队列，也不会给老板发推送。若先按「推荐/待定」入队、之后改判「不推荐」，系统会自动撤回（状态记为「终试未通过」，备注写明「线下复试判定不推荐，自动跳过终试」）。
3. 点「通过终试」或「不通过」，可填一句备注
4. 决策弹窗里会先给一份**速览**：优点 / 风险 / 待确认问题的条数，待确认问题可勾选（勾上 = 已当面问过）；弹窗顶部会显示已确认的终面时间

**队列二：待录用审批（HR 已提交，等老板批准）**

1. HR 在「录用 / 入职」页起草 Offer 并提交审批后，进入这块队列
2. 点「去审批」→ 同意 / 驳回，可填意见
3. 结果实时回到 HR 侧，HR 继续把 Offer 发给候选人（候选人页面可接受 / 拒绝，并签收）

**闸门规则（重要）**：

| 候选人终试状态 | 能否发起 Offer |
|-|-|
| 待终试 | ❌ 拒绝，先请老板拍板 |
| 终试不通过 | ❌ 拒绝 |
| 终试通过 | ✅ 可以发起 |
| 未走终试（10-20 之前的历史汇总） | ✅ 放行，不影响存量 |

> **老板侧现在有飞书主动推送**：候选人进入「待终试」时自动发卡片 + 待办（收件人 `FEISHU_BOSS_OPEN_IDS`，独立开关 `FEISHU_FINAL_PENDING_NOTIFY_ENABLED`）；未配置老板收件人时静默跳过，不影响业务。  
> **终端面时间后不会通知 HR/店长**（当前只落库展示），如需通知可后续补。  
> **老板只看得到「老板操作台」一个菜单**，HR 的初筛、模板、汇总等页面都不可见。

## 五、两个特殊分支

### 5.1 免初筛岗位

岗位标记「免初筛」后：上传简历**不做 AI 打分**，直接为每位候选人生成 AI 面试链接；汇总时不计初筛分，权重自动重新归一化。

**适合场景**：简历量不大、想快速铺开面试时。

### 5.2 到店直招（现场面试）

候选人不带简历、直接到门店找店长：

| 步骤 | 操作 |
|-|-|
| 1 | 「线下复试」页 → 点「到店直招」 |
| 2 | 一次建档：岗位 + 姓名 + 手机号 + **来源渠道** |
| 3 | 店长在**飞书妙记**里录音，把**妙记标题写成候选人姓名**，录完系统按姓名自动匹配并拉取逐字稿、生成 AI 参考分。标题写错或漏写时，在面试记录里点「粘贴录音链接」贴入妙记链接即可补转写 |
| 4 | 若自动识别没成功，点「绑定妙记」把妙记链接粘贴进去，系统立即拉逐字稿 + 评分 |
| 5 | 面试后人工打分（口径同线下复试），可参考 AI 分采纳 |

**注意**：

- 同一候选人**同一岗位**重复建档会被拒绝（避免重复提交）
- 同「姓名 + 手机号」会复用同一份候选人档案
- 汇总里会标明「来源 = 到店直招」

> **录音不落服务器**：录音存放在飞书妙记，系统只取逐字稿与评分。  
> **依赖一次授权**：自动拉取需要 HR 先在「妙记授权」页用**本人飞书账号**扫码完成设备授权（约 30 天有效，过期需重新授权）；未授权时录音仍能人工打分，只是拿不到逐字稿和 AI 参考分。

## 六、分数是怎么算出来的

| 分数 | 算法 |
|-|-|
| 初筛分 | 按 JD 四维打分（技能匹配 / 经验相关 / 稳定性 / 素质与态度），权重归一化后重算百分制 |
| AI 面试分 | 逐题按模板 rubric 打分 → 各维度均分 × 权重 → 百分制 |
| 线下复试分 | HR 在后台录入（可带维度明细）；到店直招可一键采纳妙记转写的 AI 参考分 —— 店长不操作系统，只负责录音 |
| 最终加权分 | 初筛 × 0.2 + AI 面试 × 0.4 + 线下 × 0.4（缺环节时重新归一化） |

**档位**：≥ 80 强烈推荐　｜　≥ 65 推荐　｜　≥ 50 待定　｜　< 50 不推荐

> **终试不打分**：终试只产生「通过 / 不通过」的结论，不参与加权分，但它决定能不能发 Offer。  
> **发起 Offer 的两个门槛**：最终加权分 ≥ 65，且终试已通过（历史数据除外）。

## 七、飞书会推什么给你

| # | 触发时机 | 形态 | 内容要点 |
|-|-|-|-|
| ① | 简历初筛完成 | 卡片 | 岗位、本次统计、推荐名单（含 AI 面试链接） |
| ② | 简历初筛完成 | 待办 | 候选人、分数、面试链接、截止时间 |
| ③ | AI 面试完成且达标 | 消息 | 候选人、综合分、录用建议、维度得分 |
| ④ | 汇总落库完成 | 卡片 | 「建议发放 offer」与「建议复核后决定」两组 |
| ⑤ | 汇总落库完成 | 待办 | 待复核人数、两组候选人与三段分数 |
| ⑥ | Offer 每次状态变化 | 卡片 | 提交审批、审批结果、候选人接受 / 拒绝、过期、入职 |

- 收件人按**部门实时解析在职成员**，新人自动纳入、离职自动过滤，无需手工维护名单
- 推送失败**不影响业务落库**，可到对应页面手动补推
- **老板侧推终试待确认**（`FEISHU_FINAL_PENDING_NOTIFY_ENABLED` + `FEISHU_BOSS_OPEN_IDS`）：候选人进入待终试时发卡片 + 待办；Offer 审批仍登录「老板操作台」查看

## 九、候选人那边会看到什么

1. 打开链接 → 阅读并同意《安全知情协议》
2. 看到**开场白**：问候语 + 公司介绍 + 答题说明
3. 逐题作答，页面显示进度（第 X / Y 题）
4. 回答较浅时出现追问提示
5. 全部答完显示「面试已完成」

**告知候选人的话术建议**：「这是一场 AI 面试，大约 15\~30 分钟。请尽量结合真实经历具体作答，回答越具体，AI 的判断越准。中途可以退出，重新打开链接会接着上次继续。」

## 十一、遇到问题怎么反馈

请在《**飞书试用反馈收集表**》（多维表格）里记一条，字段按提示填：

1. **提出人 + 角色**（HR / 店长 / 老板 / 候选人）
2. **所属模块**（哪个页面出的问题）
3. **问题描述**（做了什么操作、期望什么、实际发生了什么）
4. **我的建议**（你希望怎么改）
5. **严重程度**（阻塞 / 高 / 中 / 低）

有截图更佳。每周汇总一次，按「阻塞 → 高 → 中 → 低」的顺序处理，处理结果会回填在表里。
