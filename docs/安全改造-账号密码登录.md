# 安全改造：后台账号密码登录与鉴权

> 改造时间：2026-10-15
> 目标：杜绝"任何人知道 URL 就能进入后台看到全部候选人数据"
> 约束：**候选人端（面试 / Offer 确认）必须保持公开**，否则面试者拿不到链接

---

## 1. 改造前的问题

审计结论：**项目当时是零鉴权**。

- 前端 `router/index.js` 的 `/console/*` 十个页面**没有路由守卫**，直接输网址即可打开；
- 后端 `api/deps.py` 只有 `get_db()` 与 `ok()`，**没有任何认证依赖**，
  `main.py` 挂载的 7 个 router 全部裸奔；
- nginx 只做反向代理，没有 `auth_basic` 之类。

暴露面（全部匿名可读**可写**）：

| 模块 | 危害 |
|---|---|
| `GET /admin/sessions`、`/sessions/{id}/report` | 候选人姓名、手机、完整对话全文与评分报告 |
| `POST/PUT/DELETE /admin/jobs`、`/templates` | 可删岗位、删模板 |
| `POST /admin/screenings/upload`、`GET /screenings/{id}` | 简历 PDF 原件 |
| `GET /admin/offline-interviews/{id}/audio` | 面试录音音频 |
| `GET /admin/summary` | 全员分数与排名 |
| `POST /admin/offers/{id}/approve`、`/onboard` | 可直接审批 Offer、标记入职 |
| `GET /api/scores/candidate/{id}` | 任意 id 遍历候选人评分 |
| `GET/PUT /admin/company-profile` | 任意改写对外话术 |

典型攻击：浏览器地址栏粘贴 `http://<host>:3000/console/sessions` 看光所有候选人；
`DELETE /admin/jobs/1` 删掉岗位；`POST /admin/sessions` 带自己的简历无限发起 AI 面试烧 LLM 费用。

## 2. 改造后的访问边界

```
                    同一域名（http://host:3000）
  ┌────────────────────────────┬────────────────────────────┐
  │  候选人端 · 保持公开        │  管理后台 · 必须登录        │
  │  /i/{token}                │  /console/*   10 个页面     │
  │  /o/{token}                │  /admin/*     43 个接口     │
  │  /interview/*  /offer/*    │  /auth/users  账号管理      │
  └────────────────────────────┴────────────────────────────┘
                     ▲                    ▲
                     │               账号密码登录
              不可猜 token 即凭证     + CSRF + 防爆破
```

**关键设计**：候选人端的 URL `token` 是 UUID 级不可猜凭证，**它本身就是鉴权**，
因此这两个入口不能也不需要账号密码 —— 否则面试者点开链接会被要求登录。

评分查询接口 `/api/scores/candidate/{id}` 面向外部系统（无浏览器会话），
单独走 `X-API-Key`，与后台登录态分离。

## 3. 认证与授权设计

### 3.1 会话方案：服务端 Session + HttpOnly Cookie

| 项目 | 取值 |
|---|---|
| 凭据载体 | 随机 token（`secrets.token_urlsafe(32)`），存于 Cookie `ia_session` |
| Cookie 属性 | `HttpOnly` + `SameSite=Lax` + `Path=/`（`Secure` 由配置控制） |
| 服务端存储 | 只存 `sha256(token)`，**数据库被读走也无法直接冒用会话** |
| 有效期 | 12 小时（`AUTH_SESSION_HOURS`，可配） |
| CSRF 值 | 随机值存会话表，同时下发非 HttpOnly 的 Cookie `ia_csrf` |

**为什么不用无状态 JWT**：需求明确要求"重置密码后旧会话失效""Token 有服务端撤销能力"。
无状态 JWT 要做到这点必须额外造一张撤销名单表，反而比直接存会话更复杂、更易出错。

会话可被三种方式立即撤销：**登出**（撤销当前）、**本人改密**（撤销其他全部）、
**管理员重置密码 / 停用账号**（撤销该账号全部）。

### 3.2 密码存储

- 算法：**Argon2id**（`argon2-cffi`），参数 `m=64MiB / t=3 / p=4`（高于 OWASP 推荐档）
- 校验走 `PasswordHasher.verify`（算法内部恒定时间比较），业务代码不手写 `==` 比哈希
- **绝不接受**明文、MD5、SHA1/SHA256 裸哈希或自研哈希（有测试专门断言 MD5/SHA1 无法通过校验）
- 密码强度：≥10 位，含 大写/小写/数字/符号 **至少三类**，不得命中常见弱口令
  （内置弱口令表含 leet 变形展开、中文拼音、以及品牌定制词如 `benerniang123`），
  且不得包含用户名或邮箱前缀

### 3.3 账号来源：**不开放自助注册**

这是内部招聘系统，开放注册等于把候选人隐私（简历、面试录音、评分）向公众敞开。
账号只有两个创建入口：

1. **CLI 脚本**（服务器运维）：`backend/scripts/create_admin.py`
2. **后台接口** `POST /auth/users`（仅 `admin` 角色）

> 需求原文中的"用户注册"与内部系统的安全目标冲突，已确认为**不开放注册**。

### 3.4 CSRF 防护

`SameSite=Lax` + **double-submit 三处比对**：请求头 `X-CSRF-Token`
= 非 HttpOnly Cookie `ia_csrf` = 服务端会话中的 `csrf_token`。
只比"头 vs Cookie"挡不住"攻击者自己写一个 Cookie"，与库中记录比对才闭环。

所有 `POST/PUT/PATCH/DELETE` 自动校验（含 `logout`，防止被跨站强制登出）。

### 3.5 防爆破

| 维度 | 策略 |
|---|---|
| IP 维度 | 15 分钟内失败 ≥10 次即拒绝（复用 `audit_logs`，不额外建表） |
| 账号维度 | 连续失败 5 次锁定 15 分钟，之后按 **2 的幂指数退避**，封顶 24 小时 |
| 用户枚举 | 账号不存在时仍执行一次等价哈希校验（**恒定时间兜底**） |

失败文案只有两句，且**不泄露账号是否存在**：

- 凭据错误（含账号不存在、账号停用）→ `用户名或密码错误`
- 限流 / 锁定 → `登录尝试过于频繁，请稍后再试`

### 3.6 审计日志

`audit_logs` 表记录：登录成功/失败/锁定、登出、改密、建号、停用、撤销会话、
以及**所有成功的后台写操作**（由 ASGI 中间件统一记录，业务代码无需埋点）。

写入前强制脱敏：形如 `password=xxx` / `token: xxx` / `api_key=xxx` 的片段一律替换为 `***`。
**不记录**密码明文、密码哈希、会话 token 原文、CSRF 值。

`actor_id` 用 `ON DELETE SET NULL` 并冗余 `actor_name`，保证账号被删后日志仍可追溯。

### 3.7 安全基线

- 安全响应头：`X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、
  `Referrer-Policy: no-referrer`、`Permissions-Policy`、`Cross-Origin-Opener-Policy`
- CSP：生产由 nginx 下发（`default-src 'self'` 等）；本机 Vite dev 因有内联脚本，默认关闭
- CORS：仅按白名单放行，代码层面**过滤掉 `*`**；同域部署留空即不开放跨域
- 接口文档 `/docs` `/redoc` `/openapi.json` 可配置关闭（生产建议关）
- 统一错误处理沿用现有 `BizError`：401/403 只返回通用文案，堆栈只进服务端日志

### 3.8 注入类风险复核（本次一并检查）

| 类别 | 结论 |
|---|---|
| SQL 注入 | **无** —— 全库走 SQLAlchemy ORM，没有字符串拼接 SQL |
| 命令注入 | **无** —— `subprocess` 仅用于调 `lark-cli`，列表传参且无 `shell=True` |
| SSRF | **无** —— 出站请求目标固定（飞书 API），无用户可控 URL |
| 路径穿越 | **已有防护** —— 录音落盘做扩展名白名单 + `startswith(root)` 校验 |
| 开放重定向 | **已防护** —— 登录页 `redirect` 参数只接受站内路径，挡掉 `//evil.com` |

## 4. 接口说明

### 4.1 认证接口（`/auth`）

| 方法 | 路径 | 保护 | 说明 |
|---|---|---|---|
| POST | `/auth/login` | 公开 | 请求体 `{username, password}`；成功下发两个 Cookie |
| POST | `/auth/logout` | 已登录（幂等） | 撤销服务端会话并清 Cookie |
| GET | `/auth/me` | 需登录 | 返回当前用户；前端刷新页面时用它恢复登录态 |
| POST | `/auth/change-password` | 需登录 | 请求体 `{current_password, new_password}`；撤销**其他**会话 |

### 4.2 账号管理接口（仅 `admin` 角色）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/auth/users` | 账号列表（**不返回** password_hash；含锁定状态与最后登录时间） |
| POST | `/auth/users` | 创建账号 |
| POST | `/auth/users/{id}/disable` | 停用 + 撤销其全部会话 |
| POST | `/auth/users/{id}/enable` | 启用（清历史失败计数） |
| POST | `/auth/users/{id}/reset-password` | 重置密码 + 撤销其全部会话 |
| POST | `/auth/users/{id}/unlock` | 人工解除登录失败锁定 |

> 管理员**不能对自己**执行停用/重置/解锁（返回 422），避免自锁。

**命令行的定位（重要）**：命令行只用于**服务器上建第一个管理员**这一件事
（引导账号，`scripts/create_admin.py`）。此后所有建号、改密、停用、解锁
都在后台「账号管理」页面完成 —— HR 与店长**永远不需要接触服务器**，
由管理员在网页上建号后，把初始密码单独发给本人。

### 4.3 角色与权限矩阵

三种角色，权限由后端强制（前端只做菜单裁剪）：

| 功能 | 店长 store_manager | HR | 管理员 admin |
|---|---|---|---|
| 线下复试（约面 / 改期 / 打分 / 绑妙记 / 采纳 AI 分） | ✅ | ✅ | ✅ |
| 到店直招建档 | ✅ | ✅ | ✅ |
| 岗位列表（下拉框，只读） | ✅ | ✅ | ✅ |
| 删除复试记录 / 修改面试官归属 | ⛔ 403 | ✅ | ✅ |
| 简历初筛 / 面试会话 / 汇总排名 / Offer | ⛔ 403 | ✅ | ✅ |
| 岗位 / 模板 / 公司文化 增删改 | ⛔ 403 | ✅ | ✅ |
| 账号管理（`/auth/users`、`/console/accounts`） | ⛔ 403 | ⛔ 403 | ✅ |

- 店长登录后菜单只有「线下复试」一项，首页直接落在线下复试页
- 权限挂载方式：HR 职责路由在 `main.py` 挂 `require_role(ADMIN_ROLE, HR_ROLE)`；
  offline 路由登录即可进、端点级再加限（如删除限 HR）；
  `require_role` 闭包带 `_ia_allowed_roles` 标记，`tests/test_role_matrix.py`
  会枚举全部路由核对矩阵，**新增管理端路由忘挂角色会导致 CI 失败**
- 已知边界：**角色级**隔离（店长可见全部门店的线下复试记录）。
  数据模型当前没有门店概念（岗位不挂门店、地点是自由文本）；
  若将来要"店长只看本店"，需先引入 stores 表并给记录加门店外键

### 4.4 评分查询接口

`GET /api/scores/candidate/{id}` 需要请求头 `X-API-Key: <SCORES_API_KEY>`。
**未配置密钥时接口一律拒绝（503）** —— 安全默认是"不配置就不放行"，而不是"不配置就全放开"。

## 5. 前端页面

| 路径 | 说明 |
|---|---|
| `/login` | 登录页（用户名 + 密码），已登录用户访问会自动跳回后台 |
| `/console/*` | 后台页面，未登录会被路由守卫拦到 `/login?redirect=...`；角色不符跳回自己能看的首页 |
| `/console/accounts` | **账号管理页（仅管理员）**：建号 / 停用启用 / 重置密码 / 解锁 |
| `/i/{token}`、`/o/{token}` | 候选人页，**保持公开** |

- 顶部导航右侧显示当前用户与角色标签（管理员 / HR / 店长），下拉可"修改密码 / 退出登录"
- 账号管理页建号后请把初始密码**单独发给本人**（不建议发群），并提醒首次登录后改密；
  重置密码的结果只展示一次（后端只存哈希，之后谁都查不到明文）
- axios 拦截器统一：携带 Cookie、写操作自动加 `X-CSRF-Token`、
  收到 401 时跳登录（**仅 `/console` 路径下触发**，不干扰候选人页）
- 路由守卫只是体验层；**真正的访问控制在后端依赖上**

## 6. 部署注意事项（**上线前必做**）

### 6.1 创建初始管理员（**只需一次，只对服务器运维者**）

```bash
cd backend
# 本地：密码交互输入，不回显、不进 shell history
.venv/bin/python scripts/create_admin.py create --username admin001 --role admin --display-name "管理员"

# 服务器（docker compose 部署）：在 api 容器内执行同一条命令
sudo docker compose exec api python scripts/create_admin.py create --username admin001 --role admin
```

系统**没有任何默认账号密码**，不执行这一步就没有账号能登录后台。

> **命令行只用于这一处引导。** 建好第一个管理员后：
> - HR / 店长的账号由管理员登录网页 →「账号管理」页创建（无需 SSH）；
> - 忘记密码由管理员在网页上重置（结果只展示一次，当场转交）；
> - 停用离职人员、解除锁定同样在网页上完成。
>
> 换言之：**只有服务器运维者碰命令行，其他所有人只碰浏览器。**

**服务器自身的防线**（账号体系管不到的部分，需另行配置）：

- SSH 只允许密钥登录（`PasswordAuthentication no`），禁用 root 直登；
- 云防火墙只放行 22 / 80 / 443，数据库端口（5432）绝不对外；
- `.env` 与 `.env.local` 权限收紧（`chmod 600`），它含 LLM 密钥与飞书凭据。

理由：任何能拿到服务器 shell 的人都能直接读 `.env`、连数据库、改代码 ——
这已经不是"账号系统"能拦截的层级，必须靠 SSH 与网络层防护。

### 6.2 新增环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `AUTH_SESSION_HOURS` | 12 | 会话有效期 |
| `AUTH_COOKIE_SECURE` | false | **启用 HTTPS 后必须改为 true** |
| `AUTH_COOKIE_DOMAIN` | 空 | 同域部署无需设置 |
| `AUTH_LOGIN_MAX_FAILURES` | 5 | 触发锁定的连续失败次数 |
| `AUTH_LOGIN_LOCK_MINUTES` | 15 | 首次锁定时长（指数退避） |
| `AUTH_LOGIN_RATE_WINDOW_SECONDS` | 900 | IP 限流窗口 |
| `AUTH_LOGIN_RATE_MAX_ATTEMPTS` | 10 | 窗口内允许的失败次数 |
| `SCORES_API_KEY` | 空 | 外部系统评分接口密钥，`openssl rand -hex 32` 生成 |
| `CORS_ALLOW_ORIGINS` | 空 | 跨域白名单，**禁止填 `*`** |
| `SECURITY_HEADERS_ENABLED` | true | 安全响应头总开关 |
| `SECURITY_CSP_ENABLED` | false | 本机 dev 关；生产由 nginx 下发 CSP |
| `ENABLE_API_DOCS` | true | **生产建议改 false**，避免暴露接口结构 |

### 6.3 数据库迁移

```bash
cd backend && alembic upgrade head   # 0010 → 0011_admin_auth
```

新建三张表：`admin_users`、`admin_sessions`、`audit_logs`。**不含任何初始数据。**

### 6.4 启用 HTTPS（强烈建议）

当前 Cookie 的 `Secure` 默认关闭，因为没有 HTTPS 时打开会导致浏览器不回传 Cookie
（表现为"登录成功后立刻掉线"）。启用 HTTPS 后请：

1. 设置 `AUTH_COOKIE_SECURE=true`
2. 打开 `frontend/nginx.conf` 里注释掉的 HSTS 头
3. 服务器防火墙只放行 443，80 端口做 301 跳转

### 6.5 密钥轮换

| 密钥 | 轮换方式 |
|---|---|
| 用户密码 | 本人改密（`/auth/change-password`）或管理员重置（自动撤销全部会话） |
| 会话 token | 无需手动轮换：每次登录都是新随机值，12 小时自动过期 |
| `SCORES_API_KEY` | 改 `.env` → 重启 api 容器 → 通知外部系统同步更新 |

### 6.6 运维提示

- 会话表会随登录次数增长，可定期执行清理（保留 7 天）：
  `python -c "from app.db.session import SessionLocal; from app.services.auth import prune_expired_sessions; db=SessionLocal(); print(prune_expired_sessions(db))"`
- 登录失败排查：`SELECT * FROM audit_logs WHERE action LIKE 'auth.login%' ORDER BY occurred_at DESC LIMIT 50;`
- **若日志里出现 `后台写操作未被鉴权保护` 的 ERROR**，说明有新路由漏挂 `require_user`，需立即修

## 10. 残留风险与后续待办

### 需要在部署环境做的事

1. **创建初始管理员账号**（见 6.1）—— 不做就没有账号能登录
2. **启用 HTTPS 并设 `AUTH_COOKIE_SECURE=true`**，同时打开 nginx 的 HSTS
3. **设置 `SCORES_API_KEY`**，否则外部评分接口保持 503（这是有意的安全默认）
4. **生产改 `ENABLE_API_DOCS=false`**，避免接口结构外泄
5. 服务器 `.env` 补上 6.2 的新增变量（缺省值可用，但建议显式声明）

### 已知残留风险（本轮未覆盖）

| 风险 | 说明 | 建议 |
|---|---|---|
| 无 HTTPS 时 Cookie 明文传输 | 当前服务器若仍是 HTTP，会话 Cookie 可被同网段嗅探 | 尽快上 HTTPS |
| 无二次验证（2FA） | 密码泄露即失守 | 后续可接飞书扫码登录作为第二因子 |
| `X-Forwarded-For` 可伪造 | 影响限流与审计 IP 的准确性（**不影响鉴权**） | 部署时确保 nginx 是唯一入口，不要直连 api 端口 |
| 审计日志不会自动清理 | 表会持续增长 | 定期执行 `prune_expired_sessions` 同类清理，或加日志归档 |
| 无门店级数据隔离 | 店长可见全部门店的线下复试记录（角色级隔离） | 需先引入 stores 表并给记录挂门店外键 |
| 未做依赖漏洞扫描 | 未跑 `pip-audit` / `npm audit` | 上线前建议各跑一次 |

### 与原始需求的偏差说明

| 需求原文 | 实际实现 | 原因 |
|---|---|---|
| 「用户注册」 | **不开放自助注册**，改由管理员建号 | 内部系统开放注册 = 候选人隐私对公众敞开 |
| 「密码重置（可选）」 | **未做自助重置**，由管理员重置 | 账号量少（HR 几人），管理员重置更安全 |
| 「登录方式」 | 账号密码（飞书扫码改为后续可选） | 本轮确认以账号密码为主 |
