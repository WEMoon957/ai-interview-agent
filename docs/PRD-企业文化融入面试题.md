# 企业文化融入 AI 面试题 — 功能需求清单与实施计划（文字介绍版）

> 版本：v0.2｜ 状态：待评审｜ 关联文档：`docs/PRD.md`
> 需求方：HR（发面试链接时，题目需体现企业文化与公司现状）
> 简化约定：公司文化档案**只有一段自由文字**（HR 维护的一篇"公司介绍"），不拆结构化字段。

## 1. 背景与目标

### 现状问题

当前 AI 面试的题目完全来自 `interview_templates.questions`（模板预设问题集），与公司文化、现状完全无关：出题纯岗位技能向，考察不到价值观与吃苦耐劳；开场白是 `load_context.py` 写死的通用文案，候选人不知道公司是谁；评分 prompt 只有 JD/简历/维度，无文化匹配视角；飞书推荐卡片只带姓名+分数+链接，HR 转发时没有公司介绍话术。

### 目标

1. 题目体现文化：HR 发面试链接时，题集中包含围绕公司文化与现状设计的匹配题（如"我们正处于快速开店期、节假日最忙，你能接受吗？"），HR 可控（手写 / AI 辅助生成）。
2. 开场即感知：候选人打开链接，开场白能感受到"这家公司是谁、现在什么状况"。
3. 评分可参考：新增"文化匹配"评分维度，评分 prompt 感知公司介绍，追问可就价值观疑点做单一问题澄清。
4. 历史不受影响：公司介绍可随时更新，但已发出的面试会话按快照执行，改介绍不影响进行中的面试。

### 非目标

- 不做文化匹配度的独立录用决策（仅作为报告中的一个维度供 HR 参考）。
- 不做候选人端"公司官网"式宣传页（仅面试场景内的简介卡片）。
- 不改造线下复试与汇总链路（后续再议）。

## 2. 方案概述

HR 在后台维护一篇公司介绍文字（公司是谁 + 现状如何 + 团队氛围 + 用工特点，自由撰写）。发起面试时系统把这篇文字快照进会话；候选人打开链接后，开场白自动带上公司介绍，题目中包含文化匹配题，评分时 LLM 基于这篇介绍评估文化匹配度并可在追问中澄清价值观疑点。

四个发链接入口统一处理：`POST /admin/sessions`（单个发起）、`POST /admin/screenings/invite`（批量发起）、`/admin/screenings/upload` 直通模式（免初筛直接发链接）、初筛达标自动发起。

## 3. 功能需求清单

编号规则：`CC` = Company Culture。

### P0（本期必做）

- **CC-1 公司介绍数据模型**：新表 `company_profiles`，全局单例，核心就一个字段 `content`（TEXT，公司介绍自由文字），加 `updated_by` 与审计时间字段。
- **CC-2 文化介绍管理接口**：`GET /admin/company-profile`（读取，无则返回空）、`PUT /admin/company-profile`（整篇保存）。
- **CC-3 模板支持文化匹配题**：`interview_templates` 新增 `culture_fit` JSONB 配置（`{"enabled": bool, "dimension_key": "culture_fit"}`）；问题项新增可选字段 `culture: bool` 标记文化题，schema 宽松兼容旧数据（缺键 = 非文化题）。
- **CC-4 发链接时快照公司介绍**：四个发链接入口建会话时，把生效的 `content` 写入 `interview_sessions.company_profile_snapshot`（JSONB，如 `{"content": "..."}`）；无介绍写空对象，不阻断发链接。统一走一个 helper，单测覆盖四个入口。
- **CC-5 面试状态注入**：`InterviewState` 新增 `company_profile: dict`；`_build_initial_state` 从会话快照读取（缺省 `{}`），存量会话不受影响。
- **CC-6 开场白体现公司介绍**：`load_context` 开场白 = 通用文案 + 公司介绍文字（限长截断，如 300 字）；介绍为空时保持原文案。
- **CC-7 评分 prompt 感知公司介绍**：`SCORING_SYSTEM_PROMPT` 新增"公司介绍与文化"段落（`{company_culture}` 占位），文化题按"与公司文化/现状的匹配度"评分，价值观疑点可触发单一问题追问；介绍为空时段落整体省略。
- **CC-8 公司介绍管理页（前端）**：后台新增「公司文化」页，一个多行文本框 + 保存 + 最近更新时间；导航添加入口。
- **CC-9 模板页文化配置（前端）**：模板编辑器问题行增加"文化题"开关；提供"一键添加文化匹配维度"（插入 `culture_fit` 维度并自动归一化权重）。

### P1（随后做）

- **CC-10 AI 辅助生成文化匹配题**：模板页「AI 生成文化题」按钮，基于公司介绍 + JD 生成 3~5 道文化匹配题，人工可编辑后入库。
- **CC-11 文化匹配维度进报告**：rubric 含 `culture_fit` 时，报告维度汇总、百分制综合分与总体评价体现文化匹配结论。
- **CC-12 候选人端公司介绍卡片**：候选人端协议页同屏展示公司介绍卡片（取会话快照），先了解公司再答题；`GET /interview/{token}` 响应新增 `company_intro`。
- **CC-13 飞书卡片附公司介绍一句话**：`build_screening_card` / `build_screening_task` 头部追加公司介绍首句，HR 转发有话术。

### P2（后续）

- **CC-14 文化匹配效果分析**：文化匹配分与实际录用结果的关联分析，反哺题库。
- **CC-15 文化题库沉淀**：按岗位类型沉淀文化匹配题，支持从历史模板复用。
- **CC-16 多品牌多档案**：按品牌维护多篇介绍，岗位/模板绑定指定档案。

## 4. 运行时注入链路

```text
HR 维护公司介绍文字（CC-2）
        │
HR 发起面试（sessions / screenings/invite / 直通 / 自动发起）
        │  快照生效介绍 → interview_sessions.company_profile_snapshot（CC-4）
        ▼
候选人打开 /i/{token}
        │  _build_initial_state 读快照 → state.company_profile（CC-5）
        ▼
load_context  开场白 = 通用文案 + 公司介绍文字（CC-6）
        ▼
ask_question  预设问题（含 culture:true 的文化匹配题）逐题提问
        ▼
evaluate      prompt 注入公司介绍；文化匹配维度参与打分；
              价值观疑点 → 单一问题追问（CC-7）
        ▼
final_report  文化匹配维度进汇总与总结（CC-11，P1）
```

## 5. 数据与接口变更汇总

数据模型：新增 `company_profiles`（id, content, updated_by, created_at, updated_at，单例）；`interview_templates` 增加 `culture_fit` JSONB，questions 元素增加可选 `culture` 字段；`interview_sessions` 增加 `company_profile_snapshot` JSONB。全部走 Alembic 迁移，旧数据 NULL 兼容。

接口：`GET/PUT /admin/company-profile`（P0）；`POST /admin/templates/culture-questions`（P1，AI 生成文化题）；`GET /interview/{token}` 响应新增 `company_intro`（P1）。

前端：新增「公司文化」页（P0）；`Templates.vue` 增加文化题开关与维度快捷添加（P0）、AI 生成文化题（P1）；`Interview.vue` 协议页公司介绍卡片（P1）。

## 6. 实施计划

| 阶段 | 内容 | 工期 | 验收 |
| --- | --- | --- | --- |
| M1 数据与接口 | CC-1/2/3/4 | 2 天 | 迁移可升级可回滚；档案读写通；四个入口建会话后快照非空 |
| M2 运行期注入 | CC-5/6/7 | 1~2 天 | 无介绍时行为与现状零差异（回归）；有介绍时开场白与评分 prompt 含介绍；存量会话无感 |
| M3 前端 | CC-8/9 | 2 天 | HR 页面维护介绍并发起带文化题的面试，全流程跑通 |
| M4 P1 增强 | CC-10~13 | 3~4 天 | 端到端：发链接 → 候选人见公司介绍 → 答文化题 → 报告含文化匹配分 |
| M5 回归上线 | 全链路回归 + 文档更新 | 1 天 | 既有测试全绿；接口文档/使用说明同步 |

### 验收标准

- 介绍为空（新部署默认态）时，面试链路行为与改造前零差异（有用例覆盖）。
- HR 维护介绍后发起的面试：开场白包含公司介绍；`culture: true` 题目正常提问、评分、追问。
- 会话创建后修改介绍，进行中/后续面试仍用旧快照（快照隔离有用例）。
- 存量会话（快照为 NULL）正常继续，无 500。
- 飞书卡片构造纯函数有单测（含介绍为空降级）。

### 风险与对策

- LLM 文化题打分漂移：prompt 显式给文化题评分锚点，维度描述写清"与公司文化/现状匹配度"判定标准。
- 开场白过长：介绍限长截断（300 字），前端页面有字数提示。
- 快照遗漏：四个入口统一走 `_snapshot_company_profile(db)` helper，单测覆盖。
- 旧模板无 culture 字段：schema 宽松兼容，不做数据修补。
