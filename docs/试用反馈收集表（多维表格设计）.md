# 试用反馈收集表（多维表格）设计

> 用途：试行期内，HR / 店长 / 候选人在使用招聘系统过程中，按条记录问题与建议。
> 形态：飞书多维表格（Base），建议命名 **《招聘系统 · 试用反馈收集表》**。
> 配套文档：`docs/招聘全流程操作指引（试行版）.md`（第十一节引导使用者来这里反馈）。

## 1. 字段设计

| # | 字段名 | 类型 | 说明 / 选项 |
| --- | --- | --- | --- |
| 1 | 编号 | 自动编号 | 系统生成，如 `#1` |
| 2 | 提出人 | 文本 | 反馈人姓名 |
| 3 | 角色 | 单选 | HR / 店长 / 候选人 / 其他 |
| 4 | 提出日期 | 日期 | 默认当天 |
| 5 | 所属模块 | 单选 | 岗位管理 / 公司文化 / 面试模板 / 简历初筛 / AI 面试 / 线下复试 / 评分报告 / 数据汇总 / 飞书推送 / 其他 |
| 6 | 问题类型 | 单选 | 功能异常 / 体验建议 / 功能缺失 / 数据不对 / 使用咨询 |
| 7 | 严重程度 | 单选 | 阻塞 / 高 / 中 / 低 |
| 8 | 问题描述 | 多行文本 | 做了什么操作 → 期望什么 → 实际发生了什么 |
| 9 | 我的建议 | 多行文本 | 希望怎么改（可留空） |
| 10 | 处理状态 | 单选 | 待处理 / 处理中 / 已解决 / 暂不处理 |
| 11 | 处理人 | 文本 | 认领问题的开发 / 负责人 |
| 12 | 处理说明 | 多行文本 | 结论、原因、替代方案 |
| 13 | 解决日期 | 日期 | 标记「已解决」时填写 |

## 2. 建议视图

| 视图 | 类型 | 筛选 / 分组 |
| --- | --- | --- |
| 全部反馈 | 表格 | 按提出日期倒序 |
| 待处理 | 表格 | 处理状态 = 待处理，按严重程度分组（阻塞 → 高 → 中 → 低） |
| 按模块看 | 看板 | 分组字段 = 所属模块 |
| 我的 | 表格 | 提出人 = 当前用户 |

## 3. 示例记录（建档时填入，便于使用者照格式填）

| 提出人 | 角色 | 所属模块 | 问题类型 | 严重程度 | 问题描述 | 我的建议 | 处理状态 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 示例-李俊颖 | HR | 公司文化 | 体验建议 | 中 | 公司介绍写了 500 字，但开场白只展示前 300 字，后面看不到 | 希望能提示得更醒目，或在预览里标出截断位置 | 已解决 |
| 示例-门店店长 | 店长 | 线下复试 | 功能缺失 | 高 | 到店直招录了音，但系统不会自动转成文字，还是要我自己打分 | 希望能自动转写并给个参考分 | 待处理 |

## 4. 创建命令（权限就绪后执行）

```bash
# 创建多维表格
lark-cli base +base-create --as user --name "招聘系统 · 试用反馈收集表"

# 之后按 §1 建字段、按 §3 灌示例记录（+table-create / +field-create / +record-create）
```
