# AI 面试系统 · API 接口文档

> 版本：v0.2 ｜ 更新时间：2026-10-15
> 本文档供**外部系统接入**使用，涵盖系统全部 HTTP 接口，覆盖招聘全链路：**简历初筛 → AI 面试 → 线下复试 / 到店直招 → 招聘汇总**。

---

## 一、基础信息

### 1.1 Base URL

| 环境 | 地址 |
| --- | --- |
| 本地开发 | `http://localhost:8000` |
| 公网（测试） | `https://net-dare-watching-transcription.trycloudflare.com`（经前端代理，实际后端为 8000 端口） |

> ⚠️ 公网地址为临时域名，会随内网穿透重启而变化；生产接入请使用正式域名。

### 1.2 鉴权

当前测试版**接口未加鉴权**，可直接调用。生产环境将增加 API Key 鉴权，届时需在请求头携带 `Authorization`。

### 1.3 统一响应格式

所有接口返回统一 JSON 结构：

```json
{
  "code": 0,
  "message": "ok",
  "data": { }
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| code | int | 0 表示成功，非 0 表示失败 |
| message | string | 提示信息 |
| data | object/array/null | 业务数据，失败时为 null |

### 1.4 HTTP 状态码

| 状态码 | 含义 |
| --- | --- |
| 200 | 成功 |
| 404 | 资源不存在 |
| 422 | 参数校验失败 |
| 500 | 服务器内部错误 |

## 二、评分查询接口（外部系统接入核心）

> 供外部系统按候选人 ID 查询其面试评分结果。

### 2.1 按候选人查询评分

```
GET /api/scores/candidate/{candidate_id}
```

| 参数 | 位置 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| candidate_id | path | string (UUID) | 是 | 候选人 ID，创建面试会话时返回 |

**响应示例（面试已完成，有报告）**

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "candidate": {
      "id": "6a48769f-af78-4cd1-9781-c3bdaa0cd776",
      "name": "张三",
      "email": "zhangsan@example.com",
      "phone": "13800000000"
    },
    "session_id": "8c412377-1436-4736-a251-8eb4f9573f1e",
    "status": "finished",
    "score": {
      "total_score": 58.1,
      "verdict": "不推荐",
      "summary": "综合评分 58.1 分（满分 100）……",
      "dim_scores": [
        {
          "key": "tech_depth",
          "name": "技术深度",
          "weight": 0.4,
          "score": 5.17,
          "weighted_score": 2.07
        }
      ]
    }
  }
}
```

**字段说明**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| candidate.id | string | 候选人 ID |
| candidate.name | string | 姓名 |
| candidate.email | string/null | 邮箱 |
| candidate.phone | string/null | 电话 |
| session_id | string/null | 最近一场面试会话 ID（无会话时为 null） |
| status | string/null | 会话状态：pending（待面试）/ running（面试中）/ finished（已完成） |
| score.total_score | number/null | 综合分（百分制 0~100），未出报告时为 null |
| score.verdict | string/null | 录用建议：强烈推荐 / 推荐 / 待定 / 不推荐 |
| score.summary | string/null | 总体评价与风险提示 |
| score.dim_scores | array | 各维度得分 |
| dim_scores[].key | string | 维度 key |
| dim_scores[].name | string | 维度名称 |
| dim_scores[].weight | number | 维度权重 |
| dim_scores[].score | number | 该维度各题均分 |
| dim_scores[].weighted_score | number | 加权得分（score × weight） |

**边界情况**

| 情况 | 返回 |
| --- | --- |
| 候选人存在但无任何会话 | `session_id` 和 `score` 均为 null，`status` 为 null |
| 有会话但面试未完成（无报告） | `status` 为 running/pending，`score` 内各字段为 null，`dim_scores` 为空数组 |
| 候选人不存在 | `code: 404`，message「候选人不存在」 |
| candidate_id 格式非法 | `code: 422` |

## 四、管理端接口

### 4.1 岗位管理

**岗位列表**

```
GET /admin/jobs
```

**创建岗位**

```
POST /admin/jobs
Content-Type: application/json

{
  "title": "店员",
  "jd_text": "负责门店日常运营…",
  "requirements": { "skills": ["服务意识", "沟通能力"] }
}
```

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| title | string | 是 | 岗位名称 |
| jd_text | string | 否 | JD 描述 |
| requirements | object | 否 | 岗位要求（JSON 对象） |

v0.2 起，创建岗位新增可选参数 `skip_screening`（bool，默认 `false`）：设为 `true` 即「免初筛岗位」，上传简历后直接生成 AI 面试链接（见「五、简历初筛接口」直通模式）。

**更新岗位**

```
PUT /admin/jobs/{job_id}
Content-Type: application/json

{ "skip_screening": true }
```

仅更新传入的字段：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| title | string | 否 | 岗位名称（传空串会被拒绝） |
| jd_text | string | 否 | JD 描述 |
| requirements | object | 否 | 岗位要求（JSON 对象） |
| skip_screening | bool | 否 | 是否免简历初筛（直接发 AI 面试） |

**删除岗位**

```
DELETE /admin/jobs/{job_id}
```

> 级联删除该岗位下的所有模板、会话、评分、报告、候选人、简历，以及相关初筛记录、线下复试与汇总快照。

### 4.2 面试模板管理

**模板列表**

```
GET /admin/templates
```

**创建模板**

```
POST /admin/templates
Content-Type: application/json

{
  "job_id": "0ddbb62d-...",
  "questions": [
    { "id": "q1", "text": "请介绍你的相关经验" }
  ],
  "rubric": [
    {
      "key": "tech_depth",
      "name": "技术深度",
      "description": "对技术原理的理解程度",
      "weight": 0.4,
      "max_score": 10
    }
  ],
  "duration_limit": 30,
  "max_follow_ups": 2
}
```

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| job_id | string (UUID) | 是 | 岗位 ID |
| questions | array | 是 | 预设问题集，每项含 `id`、`text` |
| rubric | array | 是 | 评分维度，每项含 `key`/`name`/`description`/`weight`/`max_score`，权重之和应为 1 |
| duration_limit | int | 否 | 面试时长上限（分钟），默认 30 |
| max_follow_ups | int | 否 | 每题追问上限，默认 2 |

v0.2 起，创建模板新增可选参数 `culture_fit`（object）：文化匹配配置，形如 `{"enabled": true, "dimension_key": "culture_fit"}`，缺省未启用。启用后评分将增加文化匹配维度，需配合「公司文化档案」使用（见 4.4）。

**删除模板**

```
DELETE /admin/templates/{template_id}
```

> 级联删除该模板下的所有会话、评分、报告、候选人、简历，以及相关初筛记录、线下复试与汇总快照。

### 4.3 面试会话管理

**会话列表**

```
GET /admin/sessions?job_id={job_id}&status={status}
```

> `job_id`、`status` 为可选筛选参数。返回含 `candidate_name` 字段。

**创建会话（发起面试）**

```
POST /admin/sessions
Content-Type: multipart/form-data
```

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| template_id | string (UUID) | 是 | 模板 ID |
| name | string | 是 | 候选人姓名 |
| email | string | 否 | 邮箱 |
| phone | string | 否 | 电话 |
| file | file | 否 | 简历文件（PDF/DOCX/TXT） |

**响应示例**

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "id": "8c412377-...",
    "token": "9a48add7...",
    "thread_id": "5514df57-...",
    "template_id": "5adcb923-...",
    "candidate_id": "6a48769f-...",
    "status": "pending"
  }
}
```

> ⚠️ **重要**：响应中的 `candidate_id` 就是外部系统查询评分（接口 2.1）所需的参数；`token` 是候选人的面试码（拼在 `/i/{token}` 后即面试链接）。

**删除会话**

```
DELETE /admin/sessions/{session_id}
```

> 级联删除评分、报告、简历、候选人，以及该候选人的初筛记录、线下复试与汇总快照。

### 4.4 公司文化档案（全局单例）

一段公司介绍自由文字（公司是谁 + 现状 + 团队氛围 + 用工特点），全局仅一份，供 AI 面试开场白与「文化匹配」评分维度使用。

**读取档案**

```
GET /admin/company-profile
```

未配置时返回空档案（`content` 为空串、`id` 为 null）。

**保存档案**

```
PUT /admin/company-profile
Content-Type: application/json

{
  "content": "我们是谁 + 门店现状 + 团队氛围 + 用工特点…",
  "updated_by": "HR"
}
```

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| content | string | 否 | 公司介绍自由文字（整篇覆盖保存） |
| updated_by | string | 否 | 保存人（可选） |

**响应示例**

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "id": "0f3a...",
    "content": "我们是谁……",
    "updated_by": "HR",
    "updated_at": "2026-10-14T09:00:00+00:00"
  }
}
```

**快照隔离**：保存后仅影响之后发起的面试（发链接时把当时档案快照进会话），已发出的会话不受影响；AI 面试开场白会自动带上档案内容（截断至 300 字）。

## 五、简历初筛接口

> 岗位文件夹批量上传简历 → AI 初筛打分排序 → 一键发起 AI 面试；支持「免初筛直通」模式。

### 5.1 批量上传 + 初筛 / 直通面试

```
POST /admin/screenings/upload
Content-Type: multipart/form-data
```

| 参数 | 位置 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| job_id | form | string (UUID) | 是 | 岗位 ID |
| files | form | file[] | 是 | 简历文件，可多份（PDF/DOCX/TXT） |
| folder_name | form | string | 否 | 岗位文件夹名称（仅作记录） |
| screen | form | bool | 否 | 是否 AI 打分，默认 `true`；`false` 则仅导入不评分 |
| direct_invite | form | bool | 否 | 直通面试模式开关；留空则跟随岗位 `skip_screening` |
| template_id | form | string (UUID) | 否 | 指定面试模板；留空取该岗位最新模板 |
| notify | form | bool | 否 | 是否把初荐名单推送给 HR 飞书，默认 `true` |

两种模式（由 `direct_invite` 决定，留空则跟随岗位的 `skip_screening` 开关）：

- **AI 初筛模式**（默认）：逐份解析 + AI 打分，返回按分降序的榜单；
- **直通面试模式**（免初筛岗位）：不做 AI 打分，逐份导入后直接生成 AI 面试会话，返回每人答题链接。

单份简历失败不影响整批（逐份容错，失败记入 `errors`）。初筛达标（默认 ≥ 65 分）的候选人会自动生成面试链接；初筛完成后把推荐名单以卡片推送给 HR。

**响应示例（节选）**

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "batch_id": "7c1f...",
    "job_id": "0ddbb62d-...",
    "job_title": "店员",
    "mode": "screening",
    "total": 3,
    "succeeded": 3,
    "failed": 0,
    "errors": [],
    "items": [
      {
        "id": "9a2b...",
        "candidate_id": "6a48769f-...",
        "candidate_name": "张三",
        "file_name": "张三-店员.pdf",
        "total_score": 82.5,
        "recommendation": "强烈推荐",
        "status": "screened",
        "session_id": null,
        "session_token": null,
        "interview_path": null
      }
    ],
    "notify": { "status": "sent" }
  }
}
```

`status` 取值：`imported`（仅导入）/ `screened`（已打分）/ `interview_sent`（已发起面试）；`recommendation` 按 80/65/50 分档：强烈推荐 / 推荐 / 待定 / 不推荐。

### 5.2 初筛榜单 / 详情

```
GET /admin/screenings?job_id={job_id}&batch_id={batch_id}&status={status}
GET /admin/screenings/{screening_id}
```

榜单默认按初筛总分降序（未打分排最后）；三个参数均为可选筛选条件。

### 5.3 批量发起 AI 面试

```
POST /admin/screenings/invite
Content-Type: application/json

{ "screening_ids": ["9a2b...", "9a2c..."], "template_id": "" }
```

为选中候选人创建答题链接；幂等，已发起过则复用既有会话。`template_id` 留空取该岗位最新模板。

### 5.4 手动推送初筛推荐名单

```
POST /admin/screenings/notify
Content-Type: application/json

{ "job_id": "0ddbb62d-...", "min_score": 65 }
```

把该岗位「推荐进入 AI 面试」的名单推送到 HR 飞书（主动触发，不受幂等限制）。`min_score` 留空用服务端默认（65）。

### 5.5 删除初筛记录

```
DELETE /admin/screenings/{screening_id}
```

仅删除初筛记录本身；已发起的 AI 面试会话保留（答题链接与评分不受影响）。

## 六、线下复试与到店直招接口

> 两条入口：**线上投递**（AI 面试达标后约线下面试，`source=online`）与**到店直招**（候选人直接上门，店长一次建档，`source=walk_in`）。录音统一走飞书妙记，不落服务器。

### 6.1 创建线下复试安排

```
POST /admin/offline-interviews
Content-Type: application/json

{
  "screening_id": "9a2b...",
  "scheduled_at": "2026-10-20T10:00:00+08:00",
  "location": "昆明店",
  "interviewer": "李店长",
  "interviewer_role": "store_manager"
}
```

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| screening_id | string (UUID) | 否 | 来源初筛记录 id（自动带出候选人与岗位） |
| session_id | string (UUID) | 否 | 来源 AI 面试会话 id |
| candidate_id | string (UUID) | 否 | 候选人 id（与 screening / session 二选一） |
| job_id | string (UUID) | 否 | 岗位 id |
| scheduled_at | string | 否 | 面试时间（ISO8601） |
| location | string | 否 | 面试地点 / 门店 |
| interviewer | string | 否 | 面试官姓名 |
| interviewer_role | string | 否 | 面试官角色：`hr` / `store_manager` |

可从初筛记录或 AI 面试会话自动带出候选人与岗位；两者都不传时需显式提供 `candidate_id` + `job_id`。

**响应示例（节选）**

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "id": "3d8e...",
    "candidate_id": "6a48769f-...",
    "candidate_name": "张三",
    "job_id": "0ddbb62d-...",
    "job_title": "店员",
    "source": "walk_in",
    "status": "scheduled",
    "scheduled_at": "2026-10-20T02:00:00+00:00",
    "location": "昆明店",
    "interviewer": "李店长",
    "walk_in_code": "483920",
    "transcript_status": "pending",
    "ai_score": null,
    "score": null,
    "decision": ""
  }
}
```

### 6.2 到店直招建档

```
POST /admin/offline-interviews/walk-in
Content-Type: multipart/form-data
```

| 参数 | 位置 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| job_id | form | string (UUID) | 是 | 应聘岗位 id |
| name | form | string | 是 | 候选人姓名 |
| phone | form | string | 是 | 手机号 |
| source_channel | form | string | 是 | 来源渠道，如 门店海报 / 员工介绍 / 自然到访 |
| interviewer | form | string | 否 | 面试官（店长）姓名 |
| interviewer_role | form | string | 否 | 面试官角色：`hr` / `store_manager` |
| scheduled_at | form | string | 否 | 面试时间（ISO8601，可空） |
| location | form | string | 否 | 面试门店 / 地点 |

- 一次创建候选人 + 线下复试记录（无初筛、无 AI 面试）；
- 同「姓名 + 手机号」的候选人已存在时**复用**，不重复建人；
- 同一候选人在同一岗位已有面试记录时返回 **409**（请编辑已有记录，不要重复建档）；
- 开启妙记录音开关时生成 6 位 `walk_in_code` 短码：店长在飞书妙记录音并把标题填成短码，后端轮询自动关联并拉取逐字稿。

### 6.3 列表与录音播放

```
GET /admin/offline-interviews?job_id={job_id}&status={status}&source={source}
GET /admin/offline-interviews/{offline_id}/audio?download=false
```

`status`：`scheduled`（待面试）/ `done`（已完成）/ `no_show`（未到店）/ `cancelled`（已取消）；`source`：`online` / `walk_in`。录音默认内联播放（支持 Range 拖动进度），`?download=true` 强制下载。

### 6.4 更新安排

```
PUT /admin/offline-interviews/{offline_id}
Content-Type: application/json

{ "scheduled_at": "2026-10-21T10:00:00+08:00", "status": "no_show" }
```

可改期 / 改地点 / 改面试官 / 改状态；仅更新传入的字段。

### 6.5 录入人工打分

```
POST /admin/offline-interviews/{offline_id}/score
Content-Type: application/json

{
  "score": 88,
  "dim_scores": [{ "key": "service", "name": "服务意识", "score": 9 }],
  "comment": "沟通自然，有餐饮经验",
  "decision": "pass"
}
```

录入后状态置为 `done`。`score` 为百分制 0~100；`decision`：`pass` / `hold` / `reject`。

### 6.6 妙记录音与 AI 参考分

店长用飞书妙记录音（标题填 6 位短码），后端定时轮询自动匹配妙记、拉取逐字稿并生成「整场面试 AI 参考分」（与店长人工打分并存，互不覆盖）。以下为手动通道：

```
POST /admin/offline-interviews/{offline_id}/bind-minutes
Content-Type: application/json

{ "minutes_url": "https://xxx.feishu.cn/minutes/obcnxxx" }
```

手动绑定妙记（轮询未命中时补救 / failed 重试）：识别链接后立即拉取逐字稿并评分。

```
POST /admin/offline-interviews/{offline_id}/transcribe
```

已绑定妙记的记录，手动触发转写 + 评分（重试 failed）。

```
POST /admin/offline-interviews/{offline_id}/adopt-ai-score
Content-Type: application/json

{ "decision": "pass" }
```

采纳 AI 参考分：一键回填为正式人工打分（`score` / `dim_scores` / `comment`），状态置为 `done`；暂无 AI 参考分时返回 409。

### 6.7 删除记录

```
DELETE /admin/offline-interviews/{offline_id}
```

删除线下复试记录（连同已上传的录音文件）。

## 七、招聘汇总接口

> 实时聚合招聘全链路数据（初筛分 → AI 面试分 → 线下复试分 → 综合分），支持落库快照与 HR 复核卡片推送。

### 7.1 实时聚合

```
GET /admin/summary?job_id={job_id}&only_complete={bool}
```

实时聚合全部（或指定）岗位的候选人全链路数据，不落库。`only_complete=true` 仅返回已走完全链路的候选人（初筛 → AI 面试 → 线下复试均有结果）。

**响应示例（节选）**

```json
[
  {
    "candidate_id": "6a48769f-...",
    "candidate_name": "张三",
    "screening_score": 82.5,
    "ai_interview_score": 74.0,
    "offline_score": 88.0,
    "final_score": 79.4,
    "stage": "complete",
    "final_verdict": "推荐",
    "is_complete": true,
    "is_walk_in": false,
    "summary": "综合表现……"
  }
]
```

### 7.2 汇总落库 + 推送复核卡片

```
POST /admin/summary/rebuild?job_id={job_id}&notify={bool}
```

聚合并幂等落库（一岗位一候选人一条，存在则覆盖更新）。落库后把**本次新达成全链路完成、且尚未提醒过**的候选人汇成一张卡片推送给 HR（提醒复核并办理 offer / 入职）；按候选人幂等（`notified_at`），重复点击不会重复刷屏。`notify=false` 可关闭推送。

### 7.3 手动推送汇总结果

```
POST /admin/summary/notify?job_id={job_id}
```

把已完成的汇总结果推送到 HR（忽略幂等，用于补推）；按岗位分组，每岗位一张卡片。

### 7.4 读取汇总快照

```
GET /admin/summary/snapshots?job_id={job_id}
```

读取已落库的汇总快照（按最终分降序），字段同 7.1，另含 `snapshot_at` 快照时间。

## 九、外部系统接入建议流程

招聘全链路为：**简历初筛 → AI 面试 → 线下复试 / 到店直招 → 招聘汇总**。外部系统可按需接入其中一段：

**场景 A：完整接入（从初筛起）**

1. **创建/复用岗位**：`POST /admin/jobs`（需要「免初筛直通」时设 `skip_screening=true`）
2. **创建/复用模板**：`POST /admin/templates`（可配置 `culture_fit` 文化匹配维度，见 4.4）
3. **上传简历初筛**：`POST /admin/screenings/upload`，拿到按分降序的初筛榜单
4. **发起 AI 面试**：`POST /admin/screenings/invite`，拿到候选人 `candidate_id` 与答题 `token`
5. **候选人面试**：候选人访问 `/i/{token}`，须先同意《安全知情协议》（见 8.2）
6. **约线下复试**：`POST /admin/offline-interviews`；到店直招走 `POST /admin/offline-interviews/walk-in`
7. **汇总落库**：`POST /admin/summary/rebuild`，同步推送 HR 复核卡片
8. **获取评分**：`GET /api/scores/candidate/{candidate_id}` 拿 AI 面试分；全链路综合分走 `GET /admin/summary`

**场景 B：只读评分**（已有面试数据）：只需调用接口 2.1 即可。

**场景 C：免初筛直通**：岗位设 `skip_screening=true` 后，上传简历即直接生成每人答题链接（`POST /admin/screenings/upload` 返回 `mode=direct_invite`）。

其他常见错误：

| 状态码 | 场景 | message 示例 |
| --- | --- | --- |

| 409 | 到店直招重复建档 / 暂无 AI 参考分可采纳 / 未绑定妙记就转写 | 「张三」在岗位「店员」下已有面试记录，请直接在列表中编辑或打分 |

## 十一、注意事项

1. **评分数据落库时机**：报告在候选人完成整场面试后才生成落库；面试进行中查询评分会得到 `score` 为 null。
2. **一个候选人多次面试**：评分接口取该候选人**最近一场**面试的结果。
3. **公司档案快照隔离**：修改公司文化档案只影响之后发起的面试（发链接时快照），已发出的会话沿用当时快照。
4. **到店直招幂等**：同一候选人在同一岗位重复提交返回 409，请编辑已有记录而非重复建档。
5. **录音不落服务器**：到店直招录音统一走飞书妙记（标题填 6 位短码），后端轮询自动拉取逐字稿并生成 **AI 参考分**；AI 参考分需店长「采纳」后才成为正式打分。
6. **汇总幂等**：`POST /admin/summary/rebuild` 一岗位一候选人一条覆盖更新；HR 复核卡片按候选人只推一次，`POST /admin/summary/notify` 可手动补推。
7. **删除不可恢复**：删除岗位/模板/会话会级联删除关联数据（含初筛记录、线下复试与汇总快照），调用删除接口前请谨慎。
8. **公网域名会变化**：临时域名不稳定，生产接入请使用固定域名 + 鉴权。

## 十二、Offer → 入职接口（第⑤阶段）

> 表 `offers`（迁移 `0010_offer_onboarding`）；状态机与流转规则见 `app/services/offer.py`（唯一事实源）。

### 12.1 管理端（/admin/offers）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/admin/offers` | 列表。Query：`status` / `job_id` / `store`（模糊）/ `keyword`（候选人模糊）/ `source` / `date_from` / `date_to` / `limit`。**读取前自动执行惰性过期扫描** |
| GET | `/admin/offers/stats` | 转化统计 + 漏斗。Query：`month`（YYYY-MM）/ `job_id`；返回各状态计数、接受率、入职率、未报到率与 `funnel` |
| GET | `/admin/offers/{offer_id}` | 详情（含状态时间线字段与 `offer_link`） |
| POST | `/admin/offers` | 起草（draft）。Body：`summary_id`\* / `store_name`\* / `report_date`\* / `job_title?` / `probation_days?=30` / `note?` |
| PATCH | `/admin/offers/{offer_id}` | 修改（仅 draft / rejected 可改） |
| POST | `/admin/offers/{offer_id}/submit-approval` | 提交审批 → `pending_approval`，推审批卡片给审批人 |
| POST | `/admin/offers/{offer_id}/approve` | 审批通过 → `sent`，生成 token / 确认链接 / 截止时间。Body：`note?` |
| POST | `/admin/offers/{offer_id}/reject` | 审批驳回 → `rejected`。Body：`note`\*（必填） |
| POST | `/admin/offers/{offer_id}/withdraw` | 撤回。Body：`reason?` |
| POST | `/admin/offers/{offer_id}/onboard` | 办理入职。Body：`result`\*（`onboarded` / `no_show`）/ `actual_report_date?` / `onboard_store?` / `note?`（未报到必填） |

**错误码**

| 状态码 | 场景 |
| --- | --- |
| 404 | 汇总 / Offer 不存在 |
| 409 | 该汇总已有进行中 Offer；当前状态不允许该操作 |
| 422 | 岗位已停招 / 最终分低于门槛 / 未走完全链路 / 未配置审批人 / 驳回未填意见 / 未报到未填说明 |

### 12.2 候选人端（/offer，token 即凭证）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/offer/{token}` | 查看 Offer（进入即惰性过期判断）；仅返回候选人可见字段（不含审批人等管理信息） |
| POST | `/offer/{token}/accept` | 接受（幂等；非 `sent` 返回 409） |
| POST | `/offer/{token}/decline` | 婉拒。Body：`reason_text?`（自由文本，选填） |

### 12.3 岗位在招开关

`POST/PUT /admin/jobs` 支持 `is_active` 字段（`true` 在招 / `false` 停招）；**停招后不允许再发起 Offer（422）**，已发出的 Offer 不受影响。

## 十三、Offer 环节注意事项

1. **只有审批通过才生成候选人链接**（draft / pending_approval 阶段无 token，候选人无法访问）。
2. **确认截止时间为「发出次日本地 08:00」**，由**惰性判定**流转（读取列表 / 详情 / 统计时触发），不依赖定时任务。
3. **同一汇总同时只允许一条「进行中」Offer**（draft / pending_approval / rejected / sent / accepted）；终态后可重新发起（历史留痕）。
4. **驳回后可直接修改重提**（`rejected → pending_approval`），重提会清空上一次驳回意见。
5. **卡片审批**：审批卡片带「同意 / 驳回」按钮，需启用飞书「卡片交互」事件（长连接或 HTTP 回调），详见 `docs/全流程说明.md` §11.3。
6. **前端新增路由**：后台 `/console/offers`、候选人 `/o/{token}`；代理前缀新增 `/offer`（`vite.config.js` 与 `nginx.conf` 均已补）。
