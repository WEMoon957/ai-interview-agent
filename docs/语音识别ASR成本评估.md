# 店长面试 · 语音上传转文本（ASR）成本评估

> 版本 v0.1 ｜ 2026-10-13 ｜ 针对 `interview-agent` 项目新增「候选人语音回答 → 转文本 → 进 LangGraph 评分」链路  
> 结论先行：**ASR 转写成本极低（¥0.3~~3/小时音频），一场店长面试（约 6–7 分钟语音）转写成本仅 ¥0.03~~0.3；服务器几乎不用额外花钱（走云 API 无需 GPU）。真正的大头仍是 LLM 评分，而非 ASR。**

---

## 1. 术语澄清

| 需求           | 正确术语                                       | 方向      |
| ------------ | ------------------------------------------ | ------- |
| 候选人语音回答 → 文字 | **ASR**（Automatic Speech Recognition，语音识别） | 语音 → 文本 |
| AI 用语音念题给候选人 | TTS（Text-to-Speech，语音合成）                   | 文本 → 语音 |

本需求是 **ASR**。若后续还要「AI 语音提问」（真人感面试），再单独加 TTS，成本量级与 ASR 相当（详见 §6 附注）。

---

## 2. 量级假设（测算输入，可自行替换）

| 参数         | 取值                     | 说明         |
| ---------- | ---------------------- | ---------- |
| 每场店长面试题目数  | 10 题                   | 8~12 题取中值  |
| 每题语音回答时长   | 60 秒                   | 30~90 秒取中值 |
| **每场语音总量** | **≈ 6.7 分钟 ≈ 0.11 小时** | 10 × 60s   |
| 月面试场次      | 100 / 1000 / 10000 三档  | 对应不同扩张阶段   |

> 店长面试回答普遍偏长，若按每题 90 秒、12 题，单场可达 18 分钟（0.3 小时），成本按比例 ×2.7 即可。

## 5. 服务器成本

### 5.1 走云 ASR API（推荐）

- **计算**：现有服务器（2C4G 轻量应用服务器）**无需升级、无需 GPU**，后端只做「收音频 → 调 ASR API → 文本落库 → 送 LangGraph」，负载极轻。
- **存储**：音频文件走对象存储直传（COS/OSS），后端只存 URL。单场 mp3 约 2MB，1000 场/月 ≈ 2GB；标准存储 ¥0.12/GB/月 + 下行流量 ≈ **¥10/月以内**。
- **带宽**：前端录音直传对象存储，**不占应用服务器带宽**。
- 小计：**额外服务器成本 ≈ ¥0（复用现有）+ 对象存储 ¥10/月**。

### 5.2 自建 FunASR / Whisper（不推荐起步用）

- 需 GPU 服务器：腾讯云 GPU 云服务器（T4 级）约 **¥3~6/小时**，包月 ¥3000~8000。
- 只有当**月语音量 > 数千小时**（对应数万场面试/月）时，自建 GPU 才比云 API 划算。
- 结论：**当前阶段坚决走云 API，别自建。**

---

## 6. 推荐方案与落地路径

**选型建议（按优先级）：**

1. **阿里云百炼 Paraformer-v2（¥0.288/小时）**——最便宜、中文/方言强，性价比第一；
2. **火山引擎豆包录音 2.0（¥0.67/小时）**——大模型识别质量更好，预算宽裕时优先；
3. 若想保持单一云厂商生态（项目已倾向腾讯云 Docker），可用**腾讯云录音文件识别（¥0.70/小时 大包）**。

**落地链路（改动最小）：**

```
候选人录音 → 压缩成 16k mp3/opus → 直传对象存储(COS)
   → 后端拿 URL 调 ASR API → 得到文本
   → 文本作为 answer 送入现有 graph.invoke(Command(resume=text)) → 走既有 evaluate 评分
```

- 音频压缩：16kHz、单声道、opus/mp3，存储与流量直接降到 WAV 的 ~1/10。
- 复用现有 LangGraph 链路，**评分逻辑零改动**，只在 `POST /interview/{token}/answer` 旁加一个「语音转文本」预处理。

### TTS 附注（若后续做 AI 语音提问）

- 云 TTS 按字符计费，约 ¥3~~5/万字符；一场面试念题约 2000~~4000 字符，成本 ¥1~2/场，比 ASR 贵一个量级但仍在可接受范围。
- 不建议 MVP 就上 TTS，先文字面试 + 语音回答跑通闭环。

## 7. 隐性成本与风险提醒

| 风险              | 影响                | 应对                                    |
| --------------- | ----------------- | ------------------------------------- |
| 方言/口音（店长多为本地口音） | 识别错误 → 评分失真       | 选支持方言的引擎（腾讯/火山/阿里均支持昆明话等）；加「口语转书面语」增强 |
| 口语冗余（嗯/啊/重复）    | 文本冗长，多耗 LLM token | 用大模型 ASR 或腾讯「口语转书面语」增值功能清洗后再评分        |
| 语音留存合规          | 候选人录音属个人信息        | 落库前加「知情同意」，设定留存期限                     |
| 识别失败/空文本        | 评分节点报错            | 降级策略：识别空则提示候选人重录或用文字作答，不阻塞流程          |

---

## 8. 一句话总结

> 店长面试加语音转文本，**ASR 是整条链路里最便宜的一环**：云 API 每月 ¥30~300 量级即可覆盖数千场面试；服务器复用现有、无需 GPU。真正的成本与风险在「识别质量（方言/口音）」和「后续 LLM 评分 token」，不在 ASR 单价本身。选阿里百炼 Paraformer 起步最省，火山豆包/腾讯录音是质量与生态的备选。
